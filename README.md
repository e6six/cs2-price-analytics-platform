# CS2 Index

Независимая аналитика цен предметов Counter-Strike 2: каталог на 34 000 позиций, сравнение предложений площадок, история недельных срезов, справочник источников и калькулятор обмена. Next.js (App Router), TypeScript, Drizzle ORM, PostgreSQL (в разработке — встроенный PGlite).

## Что с данными

Проект не показывает демонстрационные котировки. В репозитории лежит воспроизводимый снимок открытых данных (`data/bootstrap`, 3,1 МБ, контрольные суммы в манифесте), из которого приложение поднимает базу при первом старте:

| Показатель | Значение |
| --- | --- |
| Предметы каталога | 34 029 (скины, наклейки, кейсы, агенты, граффити, брелоки, музыкальные наборы, патчи, коллекционные предметы, ключи) |
| Предложения (котировки) | 27 717 на дату снимка |
| История | 25 850 предметов × 25 недельных дат (2026-02-08 … 2026-08-08) |
| Семантика цены | минимальная цена активного лота Steam Community Market, USD |
| Источники | [ByMykel/CSGO-API](https://github.com/ByMykel/CSGO-API) (MIT) — метаданные; [ByMykel/counter-strike-price-tracker](https://github.com/ByMykel/counter-strike-price-tracker) (MIT) — недельные срезы цен Steam |

Принципы:

- **Происхождение каждой цены фиксируется**: источник, тип цены, валюта, время снимка, ссылка на первоисточник (`cs2_price_quotes.source_url`, таблица `cs2_source_health`, манифест набора).
- **Отсутствие данных остаётся явным**: нет котировки — нет строки и в интерфейсе стоит «—», а не ноль и не оценка.
- **Непроверенные комиссии не выдаются за факт**: у площадок в справочнике стоит статус `reported`/`conflicting` со ссылкой и датой проверки, а при `conflicting` проценты вообще не показываются.
- **Ряд цен, который ведёт себя недостоверно, помечается**: если соседние недельные наблюдения расходятся более чем в 5 раз, изменения не рассчитываются (`change_7d = null`, флаг `changeSuppressed`), чтобы не публиковать «рост на 5000 %» из-за выброса.
- **Изменения сглаживаются**: текущее значение и точки сравнения (7/30/90 дней) — медианы трёх наблюдений; дата сравнения отдаётся отдельно (`change7dFrom`), потому что набор недельный и «ровно неделю назад» может не существовать.

Снимок — это не поток реального времени. Свежесть видна в интерфейсе (бейдж возраста данных) и через `GET /api/health`. Обновлённые данные добавляются синхронизацией (`npm run sync`, `POST /api/sync`) из поддерживаемых источников.

## Возможности

- Каталог: поиск по имени, фильтры (категория, оружие, редкость, коллекция, износ, StatTrak™, Souvenir, диапазон цен, только с ценой), 8 сортировок, пагинация.
- Карточка предмета: лучшая/средняя/худшая цена, спред по площадкам, изменения 7/30/90 дней с датами сравнения, график истории, таблица предложений с происхождением и устареванием, список площадок без котировок.
- Обзор рынка: свежесть данных, индекс (медиана отношений цен корзины предметов с историей), ширина рынка (растущие/падающие/без изменений), лидеры роста и падения, самые ликвидные предметы.
- Справочник площадок: статус интеграции, комиссии со статусом проверки, KYC, лимиты запросов, состояние предохранителя (circuit breaker), количество котировок.
- Источники данных: таблица источников и прогонов, состав набора bootstrap, лицензии и атрибуция, дисклеймер.
- Избранное (`localStorage`), светлая/тёмная тема, адаптивная вёрстка на русском.
- Обновление текущей цены отдельного предмета напрямую через Steam `priceoverview` из карточки предмета.
- Оценка публичного CS2-инвентаря Steam по Steam Market и внешним площадкам: SteamID64 хранится в браузере, список предметов — только в оперативной памяти сервера не более 60 секунд.
- API с единым конвертом ошибок, лимитом частоты, кэшированием и метриками Prometheus.

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:3000
```

Без `DATABASE_URL` приложение поднимает встроенный PostgreSQL (PGlite) в `.cache/pglite`, применяет миграции и импортирует набор из `data/bootstrap` — первый запуск занимает ~1,5–2 минуты, дальше база уже на диске.

Production-режим:

```bash
export DATABASE_URL=postgresql://cs2:cs2@127.0.0.1:5432/cs2_index
npm run db:migrate && npm run db:seed -- --refresh
npm run build && npm run start
```

Полный список переменных окружения — в [`.env.example`](.env.example). Секреты (токены площадок, `SYNC_TOKEN`) хранятся только в окружении.

## API

Все ответы — JSON, ошибки — `{ "error": { "code", "message", "details" }, "requestId" }`, заголовки `x-request-id`, `cache-control`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Состояние базы и данных: `200` ready, `503` empty/unavailable, свежесть снимка |
| `GET /api/items` | Каталог: `q`, `category`, `kind`, `weapon`, `rarity`, `collection`, `wear`, `stattrak`, `souvenir`, `minPrice`, `maxPrice`, `requirePrice`, `slugs` (до 60), `sort` (8 значений), `page`, `limit` (≤100) |
| `GET /api/items/{id\|slug}?range=7d\|30d\|90d\|365d` | Карточка предмета: предложения, история, показатели |
| `POST /api/items/{id}/refresh?range=…` | Запросить свежий Steam `lowest_price` для одного предмета; применяются общий лимитер Steam и cooldown из `STEAM_PRICE_REFRESH_COOLDOWN_SECONDS` |
| `POST /api/inventory/valuation` | Оценка публичного CS2-инвентаря. JSON body: `{ "steamId64": "7656119…" }`; возвращает суммы по Steam и внешним площадкам |
| `GET /api/items/{id}/history?range=…&market=…` | Временной ряд (окно отсчитывается от последней даты наблюдений предмета) |
| `GET /api/markets` | Справочник площадок и комиссий |
| `GET /api/analytics/summary` | Сводка рынка: свежесть, покрытие, индекс, ширина, лидеры |
| `GET /api/facets` | Значения фильтров с количеством предметов |
| `GET /api/sources` | Статусы источников и последние прогоны |
| `GET /api/metrics` | Метрики Prometheus (`cs2_db_up`, `cs2_items_total`, `cs2_data_age_hours`, `cs2_market_index`, …) |
| `GET /api/sync` / `POST /api/sync` | Статус синхронизации / запуск (`Authorization: Bearer $SYNC_TOKEN`) |

## Схема данных

`src/db/schema.ts`:

- `cs2_markets` — справочник площадок и датасетов: статус интеграции, требуется ли ключ, семантика цены, комиссии со статусом проверки, KYC, лимиты.
- `cs2_items` — канонические предметы (`market_hash_name`, метаданные, изображение, `popularity` = доля дат с ценой).
- `cs2_price_quotes` — снимки предложений: `price_kind`, цена, валюта, `price_usd`, `captured_at`, `source_url`, `is_live`.
- `cs2_price_history_daily` — дневные/недельные ряды (уникальность `item + market + date + price_kind`).
- `cs2_item_stats` — материализованные показатели предмета: лучшая/средняя цена, площадка-лидер, сглаженные изменения 7/30/90 дней с датами сравнения, покрытие истории, флаг `series_noisy`.
- `cs2_ingest_runs`, `cs2_source_health` — журнал прогонов и состояние источников (предохранитель, ошибки, счётчики).
- `cs2_fx_rates` — курсы ЕЦБ для нормализации валют (fallback — статические значения с пометкой `static`).

Показатели пересобираются одним проходом (`refreshItemStats`) после импорта и каждой синхронизации, поэтому каталог и сводка не выполняют оконные функции по всей истории на каждый запрос.

## Источники и соблюдение правил

- **Steam Community Market** — публичный `market/priceoverview` отдаёт текущий `lowest_price` и дневной объём. Один общий клиент ограничивает все Steam-запросы до 12/мин и 1 запроса в 4 секунды; отдельная кнопка в карточке обновляет один предмет, а повтор использует снимок в течение `STEAM_PRICE_REFRESH_COOLDOWN_SECONDS` (по умолчанию 120 сек). Массовый обход каталога вынесен в отдельный источник `steam-search` и запускается только явным прогоном — автоматически или в фоне он не работает. Полная история (`market/pricehistory`) по-прежнему требует cookie владельца аккаунта.
- **Steam Search (`steam-search`)** — живой обход каталога через публичный поиск маркета [`market/search/render`](https://steamcommunity.com/market/search?appid=730): по 10 позиций на страницу (Steam ограничивает выдачу анонимным клиентам до 10 результатов), один запрос за раз, пауза `STEAM_SEARCH_INTERVAL_MS` (по умолчанию 3 с между страницами). За прогон берётся до `STEAM_SEARCH_PAGES` страниц (по умолчанию 1000 — 10 000 позиций), обход продолжается с курсора `nextStart` из предыдущего прогона; при 429/403 прогон немедленно останавливается, а продолжение идёт следующим запуском. Никаких прокси, ротации IP и обхода CAPTCHA/Cloudflare. Каталог насчитывает ≈3550 страниц (~35 500 позиций), поэтому при 4 прогонах в сутки полный круг занимает ~сутки.
- **LIS-SKINS** — подключён официальный публичный сгруппированный JSON-прайс-лист [`csgo.json`](https://lis-skins.com/market_export_json/csgo.json), описанный в [документации](https://lis-skins.stoplight.io/docs/lis-skins/l6th4ko9av64c-json-price-lists): одна запись на `market_hash_name`, котируемая `price`, количество и отдельная unlock-цена `unlocked_price`. Для сравнения используется `price`, а не значение разблокировки. Экспорт читается одним bulk-запросом без API key. Официальный Search API требует `Authorization: Bearer …`, поддерживает cursor pagination и лимит 200 запросов/мин; документация предупреждает о задержке в несколько минут и рекомендует WebSockets для моментальных событий. Этот проект использует периодический JSON-срез, не WebSocket-поток. Компактный export не содержит гарантированной даты обновления и валюты: `LISSKINS_PRICE_CURRENCY` по умолчанию `USD`, дату получения и возможную задержку нужно учитывать.
- **SkinBaron** — подключён официальный `POST /GetExtendedPriceList` (`https://api.skinbaron.de`) из [API-документации](https://skinbaron.de/misc/apidoc/). Ключ создаётся в профиле и передаётся в JSON body (`SKINBARON_API_KEY`); адаптер посылает требуемые `Content-Type: application/json` и `x-requested-with: XMLHttpRequest`. API-схема не указывает валюту поля `lowestPrice`: по умолчанию используется EUR, её необходимо проверить и при необходимости изменить через `SKINBARON_PRICE_CURRENCY`.
- **Skinport** — публичный API `/v1/items` (валюта USD, `tradable`), данные кэшируются 5 минут; адаптер делает один bulk-запрос.
- **CSFloat** — публичный `listings/price-list`; с ключом лимиты выше.
- **BUFF163** — только авторизованная сессия (`BUFF_COOKIE`), CNY, ≤10 запросов/мин.
- **Открытые датасеты** (GitHub, MIT) — массовое обновление цен и метаданных; такой Steam snapshot не равен свежему live-запросу.
- DMarket, Tradeit и SkinsMonkey остаются планируемыми: адаптеры не подключены.

Правила проекта: не обходить CAPTCHA, Cloudflare, авторизацию и антибот-защиту; не использовать прокси для уклонения от лимитов; не выдавать непроверенные комиссии, выплаты и KYC за факт; не подменять отсутствие данных оценкой; не перепубликовать данные площадок без разрешения их условий.

## Эксплуатация

- **Свежесть**: `GET /api/health` и `cs2_data_age_hours` показывают возраст срезов; цены каждой площадки также имеют своё время захвата.
- **Автообновление bulk-источников**: для постоянно работающего хоста запустите отдельный процесс `npm run sync:watch -- --interval=5`. По умолчанию он опрашивает Skinport, CSFloat, LIS-SKINS и SkinBaron (SkinBaron пропускается без ключа). Отдельный процесс не зависит от пользовательской сессии и не запускает массовый обход Steam. Worker и веб-приложение должны использовать одну PostgreSQL `DATABASE_URL`; не запускайте оба процесса против одного каталога PGlite.
- **Steam**: текущую цену можно обновить из карточки предмета. Для регулярной синхронизации небольшого набора есть `npm run sync -- --source=steam-community --limit=50`; каждый Steam-предмет — отдельный запрос, поэтому большой лимит может выполняться долго. Внешний cron может вызывать `POST /api/sync` с `Authorization: Bearer $SYNC_TOKEN`.
- **Массовое обновление цен Steam**: `npm run sync -- --source=steam-search` обходит поиск маркета страницами по 10 позиций и продолжает с курсора — для продолжения просто запускайте команду повторно, а `--limit=N` задаёт число страниц за прогон (у этого источника лимит — страницы, а не предметы; по умолчанию `STEAM_SEARCH_PAGES=1000`, каталог ≈3550 страниц при 4 прогонах в сутки проходит полный круг примерно за сутки). Источник использует неофициальный эндпоинт, поэтому при 429/403 обход останавливается и ждёт следующего запуска, а причина остановки видна в `notes` прогона (`cs2_ingest_runs`).
- **Наблюдаемость**: структурные JSON-логи, `GET /api/metrics` (Prometheus), журнал `/api/sources`.
- **Ограничение частоты**: limiter Steam общий на процесс. При нескольких репликах каждый процесс имеет свой limiter; используйте одну реплику/внешний общий gateway и не повышайте лимит Steam без разрешения Valve.
- **Бэкапы**: для PGlite достаточно архива каталога `.cache/pglite`; для PostgreSQL — обычные процедуры резервного копирования.
- **Ретенция**: `QUOTE_RETENTION_DAYS` ограничивает хранение старых снимков предложений.

## Ограничения

- Данные bootstrap — недельные срезы; «изменение за 7 дней» на таком наборе означает ближайшее доступное наблюдение, дата всегда отдаётся в API. LIS-SKINS export также может отставать на несколько минут; быстрый повторный Steam refresh ограничен.
- Сервис не подключается к Steam-аккаунту: оценка инвентаря работает только для публичного профиля, принимает SteamID64 или URL `/profiles/{SteamID64}` (vanity `/id/...` не разрешается). До 20 000 записей загружаются максимум за 10 страниц; при большем размере UI показывает частичный результат.
- Оценка инвентаря приблизительная: использует общую цену `market_hash_name`, не учитывает конкретный float, наклейки, pattern/phase и комиссии. Steam Market сумма — Steam Wallet funds, не выводимые наличные.
- Внешние котировки в инвентаре берутся из последнего среза, возраст помечается; если цены нет, она не заменяется нулём или оценкой.
- Нет торговых операций, хранения средств, входа в Steam и уведомлений: сервис только показывает данные. Не аффилирован с Valve Corporation.
- Локализации Valve не подключены: названия предметов в канонической англоязычной форме.
- `steam-community` в bootstrap помечен `isLive: false`; запись становится live только после прямого priceoverview-запроса или нового live sync.
