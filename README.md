# CS2 Index

Независимый интерфейс аналитики предметов Counter-Strike 2: каталог, сравнение ценовых предложений, история, справочник площадок и калькулятор обмена. Приложение построено на Next.js App Router, TypeScript, PostgreSQL и Drizzle ORM.

## Статус данных — важно

Это **работающий MVP-прототип**, а не подключённый агрегатор live-котировок. Для интерфейса автоматически создаётся небольшой демонстрационный набор: 13 предметов, 8 записей справочника площадок, 104 синтетических ценовых снимка и пример 365-дневной истории.

- Все предложения помечены `isDemo: true`; история также хранит демо-флаг.
- Даты фиксации нужны для демонстрации контракта. Значения цен, динамики и выплат синтетические и не отражают текущий рынок.
- Комиссии и KYC сохранены как непроверенные (`null` / `Не проверена`); модельную выплату нельзя считать тарифом маркетплейса.
- Ни один внешний источник цен сейчас не подключён. Названия площадок приведены только в справочнике интеграций.
- Steam-аутентификация, хранение API-ключей, уведомления и торговые операции не реализованы.

Не используйте демонстрационные котировки для финансовых решений. Перед публикацией реальных данных замените seed-адаптер проверенными, разрешёнными источниками и показывайте происхождение каждого снимка.

## Возможности прототипа

- Поиск по имени, оружию и коллекции; фильтры по категории, оружию, редкости, коллекции, износу, StatTrak™ и Souvenir.
- Сортировка по популярности, цене и изменению; постраничный API каталога.
- Сравнение примеров цены покупателя и модельной выплаты продавцу с временем снимка.
- График медианной цены за 7, 30, 90 дней и год; детальная карточка с `float`, paint seed и атрибутами.
- Справочник площадок, в котором статус подключения, комиссия и KYC честно показаны как непроверенные.
- Калькулятор trade-in с редактируемыми суммами и условной комиссией.
- Локальный список наблюдения в `localStorage`, светлая и тёмная тема.
- Русскоязычный адаптивный интерфейс. Названия предметов хранятся в канонической англоязычной форме; полноценные локализации Valve пока не подключены.
- Дисклеймеры: сервис не продаёт скины, не принимает и не хранит средства, не выполняет торговые операции и не аффилирован с Valve Corporation.

## Запуск

Требуются Node.js, npm и PostgreSQL.

1. Создайте `.env` с `DATABASE_URL`, указывающим на вашу PostgreSQL-базу.
2. Установите зависимости: `npm install`.
3. Примените схему: `npx drizzle-kit push`.
4. Запустите приложение: `npm run dev`.

При первом запросе к главной странице или API каталог заполняется идемпотентными демонстрационными записями. Для production задайте отдельные секреты окружения, используйте управляемую PostgreSQL, TLS, резервное копирование и пул соединений. Не публикуйте `.env`.

## API

Все ответы с каталоговыми seed-данными содержат `demo: true`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Healthcheck приложения и соединения с PostgreSQL |
| `GET /api/items?q=awp&category=Винтовки&weapon=AWP&rarity=Тайное&collection=Коллекция%20Phoenix&wear=После%20полевых%20испытаний&stattrak=1&souvenir=1&sort=price-asc&page=1&limit=30` | Поиск, фильтры и пагинация; все параметры необязательны |
| `GET /api/items/{id}` | Метаданные, предложения и история предмета |
| `GET /api/items/{id}/history?range=7d\|30d\|90d\|365d` | Временной ряд указанной глубины |
| `GET /api/markets` | Справочник маркетплейсов, статус подключения и проверки тарифов |
| `GET /api/analytics/summary` | Сводные метрики и лидеры демонстрационного набора |

Ошибки валидации возвращаются с HTTP 400, отсутствующий предмет — с HTTP 404. В production к публичному API следует добавить rate limiting, наблюдаемость, схемы версионирования и политику кэширования.

## Схема данных

Drizzle-модели находятся в `src/db/schema.ts`:

- `cs2_items` — канонический предмет и метаданные износа/паттерна.
- `cs2_markets` — справочник площадок, статусы интеграции, комиссии и KYC.
- `cs2_price_listings` — снимок предложения: покупательская цена, расчёт выплаты, валюта, регион и `captured_at`.
- `cs2_price_history` — дневной ряд минимальной/медианной цены и объёма.

`src/lib/demo-data.ts` содержит только демонстрационные seed-значения; `src/lib/cs2-data.ts` — идемпотентное начальное заполнение и операции Drizzle. Для рабочих предложений добавьте идентификатор источника, валютный курс, тип цены, статус проверки, `source_url` и точную методику нормализации/комиссии. Нельзя подменять отсутствующую котировку оценкой: отсутствие данных должно оставаться явным.

## Подключение реальных источников

Интеграции намеренно не имитируются. Следующий этап должен использовать только публичные API, договорные фиды либо сбор, прямо разрешённый условиями площадки. До подключения:

1. Проверить документацию API, лицензию на перепубликацию и правила площадки.
2. Для каждой комиссии, выплаты, KYC-политики и регионального ограничения хранить проверенный источник и дату проверки; не показывать неподтверждённые значения как факт.
3. Ограничивать запросы, обрабатывать `Retry-After`, использовать адаптивный backoff, кэш и circuit breaker.
4. Уважать `robots.txt`, условия использования, защиту аккаунтов и ограничения доступа. Не обходить CAPTCHA, Cloudflare, JWT, авторизацию или антибот-защиту; не использовать прокси для уклонения от ограничений.
5. Фиксировать время получения и валюту для каждого снимка, хранить историю источников и отображать устаревшие цены.
6. Масштабировать каталог до полного набора предметов только из проверяемого каталога Valve/Steam, соблюдая условия распространения локализаций и медиа.

Для production-потока отдельные worker-процессы и Redis/RabbitMQ могут обрабатывать только разрешённые источники; UI и API должны продолжать работать при отсутствии цены или отказе конкретного источника. Такие workers, proxy-пул, Steam sign-in и Telegram-бот в текущем репозитории не развёрнуты.
