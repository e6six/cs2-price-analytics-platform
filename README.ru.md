## Что это — и чем не является

CS2 Index хорошо отвечает на узкий вопрос: *сколько предмет стоит сейчас, как изменилась цена и откуда взялось это число?*

- **Реальные данные снимка, а не демонстрационные котировки.** В репозитории лежит воспроизводимый открытый набор (`data/bootstrap`, 3,1 МБ, контрольные суммы в манифесте), который приложение поднимает при первом старте.
- **Живые цифры — только по явному запросу.** Текущую цену одного предмета можно обновить из Steam, а массовый обход каталога никогда не запускается автоматически или в фоне.
- **Ни торговых операций, ни хранения средств, ни доступа к аккаунту.** Оценка инвентаря читает **публичный** CS2-инвентарь без входа в Steam и без cookie. Не аффилирован с Valve Corporation.
- **Никаких выдуманных значений.** Нет котировки — в интерфейсе стоит `—`, а не `0` и не оценка. В инвентаре предмет без цены показывается без значения, а не как `$0`.

## Что с данными

| Показатель | Значение |
| --- | --- |
| Предметы каталога | 34 029 — скины, наклейки, кейсы, агенты, граффити, брелоки, музыкальные наборы, патчи, коллекционные предметы, ключи |
| Предложения (котировки) | 27 717 на дату снимка |
| История | 25 850 предметов × 25 недельных дат (2026-02-08 … 2026-08-08), 631 840 точек |
| Семантика цены | минимальная цена активного лота Steam Community Market, USD |
| Источники | [ByMykel/CSGO-API](https://github.com/ByMykel/CSGO-API) (MIT) — метаданные; [ByMykel/counter-strike-price-tracker](https://github.com/ByMykel/counter-strike-price-tracker) (MIT) — недельные срезы цен Steam |

Принципы, которые действительно проверяет код:

- **Происхождение каждой цены фиксируется** — источник, тип цены, валюта, время снимка, ссылка на первоисточник (`cs2_price_quotes.source_url`, таблица `cs2_source_health`, манифест набора).
- **Отсутствие данных остаётся явным** — нет котировки, нет строки: в интерфейсе стоит «—», а не ноль и не оценка; в инвентаре предмет без цены не заменяется нулём.
- **Непроверенные комиссии не выдаются за факт** — у площадок стоит статус комиссии `reported` / `conflicting` со ссылкой и датой проверки, а при `conflicting` проценты вообще не показываются.
- **Недостоверные ряды помечаются, а не «сглаживаются» в вымысел** — если соседние недельные наблюдения расходятся более чем в 5 раз, изменения не рассчитываются (`change_7d = null`, флаг `changeSuppressed`), чтобы не публиковать «рост на 5000 %» из-за выброса.
- **Изменения сглаживаются, а даты называются прямо** — текущее значение и точки сравнения (7/30/90 дней) это медианы трёх наблюдений; дата сравнения отдаётся отдельно (`change7dFrom`), потому что набор недельный и «ровно неделю назад» может не существовать.

Снимок — это не поток реального времени. Свежесть видна в интерфейсе (бейдж возраста данных) и через `GET /api/health`. Обновлённые данные добавляются синхронизацией (`npm run sync`, `POST /api/sync`) из поддерживаемых источников.

## Архитектура

<img src="docs/assets/architecture.ru.png" alt="Поток данных: открытые источники → сбор → хранилище → API и интерфейс" width="100%">

Адаптеры площадок работают по одному контракту (`src/lib/ingest/providers`), у прогонов есть предохранитель на каждый источник и журнал, а материализованные показатели предметов (`refreshItemStats`) пересобираются одним проходом после импорта и каждой синхронизации — поэтому каталог и сводка не выполняют оконные функции по всей истории на каждый запрос.

Весь трафик к Steam идёт через один общий клиент с глобальным лимитером (12 запросов/мин, не чаще одного запроса в 4 секунды): интерактивное обновление в карточке и массовый обход `steam-search` используют один лимитер, поэтому обход не «съедает» квоту интерфейса.

## Возможности

- **Каталог** — поиск по имени, фильтры (категория, оружие, редкость, коллекция, износ, StatTrak™, Souvenir, диапазон цен, только с ценой), 8 сортировок, пагинация.
- **Карточка предмета** — лучшая/средняя/худшая цена, спред по площадкам, изменения 7/30/90 дней с датами сравнения, график истории, таблица предложений с происхождением и устареванием, список площадок без котировок и кнопка получения текущего Steam `lowest_price` для этого предмета (cooldown `STEAM_PRICE_REFRESH_COOLDOWN_SECONDS`, по умолчанию 120 с).
- **Обзор рынка** — свежесть данных, индекс (медиана отношений цен корзины предметов к базовой дате), ширина рынка (растущие/падающие/без изменений), лидеры роста и падения, самые ликвидные предметы.
- **Оценка инвентаря** — по SteamID64 или ссылке `/profiles/…` сервис оценивает публичный CS2-инвентарь по Steam Market и внешним площадкам: поиск по списку, сортировка по стоимости строки, переключатель базы «Steam / внешние». ID остаётся в `localStorage` этого браузера, список предметов — только в оперативной памяти сервера не дольше 60 секунд и в базу не пишется.
- **Справочник площадок** — статус интеграции, комиссии со статусом проверки, KYC, лимиты запросов, состояние предохранителя (circuit breaker), количество котировок.
- **Источники данных** — таблицы источников и прогонов, состав набора bootstrap, лицензии и атрибуция, дисклеймер.
- **Калькулятор выплаты** — расчёт по реальной котировке и явно выбранной комиссии.
- **Интерфейс** — светлая и тёмная тема без «вспышки» при загрузке, локальный шрифт Inter (латиница + кириллица), клавиша `/` переводит фокус в поиск, адаптивная вёрстка, русская локализация, избранное в `localStorage`.
- **API** — единый конверт ошибок, лимит частоты, кэширование и метрики Prometheus.

## Быстрый старт

```bash
git clone https://github.com/e6six/cs2-price-analytics-platform.git
cd cs2-price-analytics-platform
npm install
npm run dev          # http://localhost:3000
```

Без `DATABASE_URL` приложение поднимает встроенный PostgreSQL (PGlite) в `.cache/pglite`, применяет миграции и импортирует набор из `data/bootstrap`. Первый запуск занимает около одной-двух минут, дальше база уже на диске. Работать должен ровно один процесс: не направляйте веб-приложение и worker `sync:watch` на один и тот же каталог PGlite.

Production-режим:

```bash
export DATABASE_URL=postgresql://cs2:cs2@127.0.0.1:5432/cs2_index
npm run db:migrate && npm run db:seed -- --refresh
npm run build && npm run start
```

Полный список переменных окружения — в [`.env.example`](.env.example). Секреты (токены площадок, `SYNC_TOKEN`) хранятся только в окружении.

## API

Все ответы — JSON, ошибки — `{ "error": { "code", "message", "details" }, "requestId" }`, заголовки `x-request-id`, `cache-control`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Состояние базы и данных: `200` ready, `503` empty/unavailable, свежесть снимка |
| `GET /api/items` | Каталог: `q`, `category`, `kind`, `weapon`, `rarity`, `collection`, `wear`, `stattrak`, `souvenir`, `minPrice`, `maxPrice`, `requirePrice`, `slugs` (до 60), `sort` (8 значений), `page`, `limit` (≤100) |
| `GET /api/items/{id\|slug}?range=7d\|30d\|90d\|365d` | Карточка предмета: предложения, история, показатели |
| `POST /api/items/{id}/refresh?range=…` | Запросить текущий Steam `lowest_price` для одного предмета; действуют общий лимитер Steam и cooldown |
| `POST /api/inventory/valuation` | Оценка публичного CS2-инвентаря. JSON body: `{ "steamId64": "7656119…" }`; возвращает цены по предметам и суммы по Steam и внешним площадкам |
| `GET /api/items/{id}/history?range=…&market=…` | Временной ряд (окно отсчитывается от последней даты наблюдений предмета) |
| `GET /api/markets` | Справочник площадок и комиссий |
| `GET /api/analytics/summary` | Сводка рынка: свежесть, покрытие, индекс, ширина, лидеры |
| `GET /api/facets` | Значения фильтров с количеством предметов |
| `GET /api/sources` | Статусы источников и последние прогоны |
| `GET /api/metrics` | Метрики Prometheus (`cs2_db_up`, `cs2_items_total`, `cs2_data_age_hours`, `cs2_market_index`, …) |
| `GET /api/sync` / `POST /api/sync` | Статус синхронизации / запуск (`Authorization: Bearer $SYNC_TOKEN`) |

## Схема данных

`src/db/schema.ts`:

- `cs2_markets` — справочник площадок и датасетов: статус интеграции, требуется ли ключ, семантика цены, комиссии со статусом проверки, KYC, лимиты.
- `cs2_items` — канонические предметы (`market_hash_name`, метаданные, изображение, `popularity` = доля дат с ценой).
- `cs2_price_quotes` — снимки предложений: `price_kind`, цена, валюта, `price_usd`, `captured_at`, `source_url`, `is_live`.
- `cs2_price_history_daily` — дневные/недельные ряды (уникальность `item + market + date + price_kind`).
- `cs2_item_stats` — материализованные показатели предмета: лучшая/средняя цена, площадка-лидер, сглаженные изменения 7/30/90 дней с датами сравнения, покрытие истории, флаг `series_noisy`.
- `cs2_ingest_runs`, `cs2_source_health` — журнал прогонов и состояние источников (предохранитель, ошибки, счётчики).
- `cs2_fx_rates` — курсы ЕЦБ для нормализации валют (fallback — статические значения с пометкой `static`).

Оценки инвентаря намеренно **не хранятся**: SteamID64 остаётся в браузере посетителя, а список предметов — только в памяти процесса.

## Источники и соблюдение правил

- **Steam Community Market** — публичный `market/priceoverview` отдаёт текущий `lowest_price` и дневной объём. Один общий клиент ограничивает все Steam-запросы до 12/мин и одного запроса в 4 секунды. Кнопка в карточке обновляет один предмет, повтор использует снимок в течение `STEAM_PRICE_REFRESH_COOLDOWN_SECONDS` (по умолчанию 120 с). Полная история (`market/pricehistory`) требует cookie владельца аккаунта — `STEAM_MARKET_COOKIE` задаёт оператор.
- **Steam Search (`steam-search`)** — живой обход публичного поиска маркета [`market/search/render`](https://steamcommunity.com/market/search?appid=730): по 10 позиций на страницу (Steam ограничивает анонимных клиентов), один запрос за раз, пауза `STEAM_SEARCH_INTERVAL_MS` (3 с) между страницами, до `STEAM_SEARCH_PAGES` (1000 страниц = 10 000 позиций) за прогон, продолжение с курсора `nextStart`. При 429/403 обход немедленно останавливается, причина видна в `notes` прогона. Никаких прокси, ротации IP и обхода CAPTCHA/Cloudflare. Каталог ≈3550 страниц (~35 500 позиций), поэтому при 4 прогонах в сутки полный круг занимает около суток.
- **Skinport** — публичный API `/v1/items` (USD, `tradable`), кэш 5 минут, один bulk-запрос.
- **LIS-SKINS** — официальный публичный сгруппированный JSON-прайс [`csgo.json`](https://lis-skins.com/market_export_json/csgo.json): одна запись на `market_hash_name` с `price` и `unlocked_price`; для сравнения берётся `price`. Bulk-запрос без API-ключа. В компактном экспорте нет гарантированной даты и валюты: `LISSKINS_PRICE_CURRENCY` по умолчанию `USD`, срез может отставать на минуты.
- **SkinBaron** — официальный `POST /GetExtendedPriceList` (`https://api.skinbaron.de`); ключ создаётся в профиле (`SKINBARON_API_KEY`). Валюта поля `lowestPrice` в схеме не указана: по умолчанию принят EUR и его нужно проверять через `SKINBARON_PRICE_CURRENCY`.
- **CSFloat** — публичный `listings/price-list`; с ключом лимиты выше.
- **BUFF163** — только авторизованная сессия (`BUFF_COOKIE`), CNY, ≤10 запросов/мин.
- **Открытые датасеты** (GitHub, MIT) — массовое обновление цен и метаданных; такой Steam-снимок не равен свежему live-запросу.
- DMarket, Tradeit и SkinsMonkey остаются планируемыми: адаптеры не подключены.

Правила проекта: не обходить CAPTCHA, Cloudflare, авторизацию и антибот-защиту; не использовать прокси для уклонения от лимитов; не выдавать непроверенные комиссии, выплаты и KYC за факт; не подменять отсутствие данных оценкой; не перепубликовать данные площадок без разрешения их условий.

## Эксплуатация

- **Свежесть**: `GET /api/health` и `cs2_data_age_hours` показывают возраст срезов; у каждой котировки площадки есть и собственное время захвата.
- **Bulk-источники по расписанию**: `npm run sync:watch -- --interval=5` отдельным процессом опрашивает Skinport, CSFloat, LIS-SKINS и SkinBaron (без ключа SkinBaron пропускается) и никогда не запускает обход Steam. Worker и веб-приложение должны использовать одну PostgreSQL `DATABASE_URL`.
- **Steam по запросу**: обновление одного предмета из карточки или `npm run sync -- --source=steam-community --limit=50` для небольшого набора (каждый предмет — отдельный запрос). Внешний cron может вызывать `POST /api/sync` с `Authorization: Bearer $SYNC_TOKEN`.
- **Массовый обход Steam**: `npm run sync -- --source=steam-search` идёт по страницам и продолжает с курсора при следующем запуске; `--limit=N` задаёт бюджет страниц. Так как эндпоинт неофициальный, 429/403 останавливает обход, а причина пишется в `notes` прогона (`cs2_ingest_runs`).
- **Наблюдаемость**: структурные JSON-логи, `GET /api/metrics` (Prometheus), журнал прогонов `/api/sources`.
- **Ограничение частоты**: лимитер Steam общий на процесс; при нескольких репликах у каждой свой — держите одну реплику или общий шлюз и не поднимайте лимит Steam без разрешения Valve.
- **Бэкапы**: для PGlite достаточно архива каталога `.cache/pglite`; для PostgreSQL — обычные процедуры резервного копирования.
- **Ретенция**: `QUOTE_RETENTION_DAYS` ограничивает хранение старых снимков предложений.

## Ограничения

- Данные bootstrap — недельные срезы; «изменение за 7 дней» означает ближайшее доступное наблюдение, дата всегда отдаётся в API. Экспорт LIS-SKINS тоже может отставать на минуты, а частый повторный Steam refresh ограничен намеренно.
- Сувенирные предметы в открытых датасетах чаще содержат выбросы — такие ряды помечаются как неустойчивые, а не «исправляются» на глаз.
- Сервис не подключается к Steam-аккаунту: оценка инвентаря работает только для публичного профиля, принимает SteamID64 или ссылку `/profiles/{SteamID64}` (vanity-ссылки `/id/…` не разворачиваются). До 20 000 записей загружаются максимум за 10 страниц; при большем размере интерфейс показывает частичный результат.
- Оценка инвентаря приблизительна: используется общая цена `market_hash_name`, без учёта float, наклеек, pattern/phase и комиссий. Сумма по Steam Market — это средства Steam Wallet, а не выводимые деньги.
- Внешние цены в инвентаре берутся из последнего среза и помечаются возрастом; если цены нет, она не заменяется нулём или оценкой.
- Нет торговых операций, хранения средств, входа в Steam и уведомлений: сервис только показывает данные. Не аффилирован с Valve Corporation.
- Локализации Valve не подключены: названия предметов в канонической англоязычной форме.
- `steam-community` в bootstrap помечен `isLive: false`; запись становится live только после прямого запроса `priceoverview` или нового live-прогона синхронизации.
- Изображения предметов загружаются с CDN Valve и не входят в репозиторий; если CDN недоступен, плитка показывает монограмму в цвете редкости.
